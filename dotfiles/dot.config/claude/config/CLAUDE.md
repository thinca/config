初めて触るプロジェクトではまず README.md や CONTRIBUTING.md を探して内容を確認し、開発者向けドキュメントがあれば目を通してください。

ツールを使って書き込み可能なディレクトリを制限しています。プロジェクトディレクトリ外への書き込みは失敗する可能性があります。
言語のツールチェインのビルドなどが失敗する場合は必要に応じて一時ディレクトリを使用してください。
1 度だけ行えばよいものの場合はユーザーに手動で行ってもらうことも検討してください。

一時ファイルはプロジェクト直下に `.tmp` ディレクトリを作成し、ここを使用してください。
使い終わった不要な一時ファイルは削除してください。


## コード中のコメントや文書について

- 基本的にはコードコメントは書かないでください。コメントは必要悪です。コードの挙動はコードで説明されるべきです。名前の付け方や関数の分け方を適切にすることでコメントがなくても意図が伝わるコードになります。what や how についてのコメントは不要です。コメントをどうしても書く場合は、以下のケースに当てはまるか確認してください。
  - why not を説明するコメント。コードが特定の手段を取らなかった理由についてはコメントでしか補足できないので、これは書いてよいです。
  - 非常に複雑なロジックを用いる場合は、理解を助けるためにロジックを説明するコメントを残してもよいです。単純なコードの説明は完全に不要です。
  - プロジェクトに別途コメントに関するルールがある場合はそちらに従ってください。
- 「A を B に変更して」という指示に対して文書を残す必要がある場合、「A をやめる」という文書は大抵の場合は不要です。最初から B であったかのような文書にしてください。
- 自然言語は既存の文章があればそれに揃えて、特に指示がなく指標もない場合は英語で書いてください。
- 図を描く場合など、文字の幅が重要な箇所では曖昧幅の文字は使わないでください。


## 外部に対してのメッセージ送信について

ユーザーが認証しているツールを使うと、ユーザー自身の権限でコメントやメッセージの送信ができますが、即座に他の人に見えるようなメッセージの送信は明示的な指示がない限りは絶対に行ってはいけません。下書き状態のように公開前にユーザーが確認できる場合は問題ありません。
指示があってメッセージを送る場合、メッセージには原則として「そのメッセージを生成したのが Claude Code であること」がわかるようなシグネチャや注釈を入れるようにしてください。
